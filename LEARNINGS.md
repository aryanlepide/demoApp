# What I learned

After each phase, the Agent asks the developer for one useful learning and records it briefly.

- **Planning:**
- **Detection:** The starter contained fixtures but no detector or runner; Node 24's built-in TypeScript stripping and `node:test` enabled dependency-free tests. Include trailing punctuation and Unicode in email boundary tests.
- **UI:** The screenshots mapped cleanly to one local shell with three routes. Keep uploads allowlisted and in memory; store only masked summaries for session-level dashboard totals.
- **Upload:** Keep the native file input visibly actionable, and make the primary button open it when no file is selected; a disabled scan button alone looks broken to users.
- **Dashboard:** Keep highest-risk file classification distinct from counts of individual findings; a Critical file can still contain Low, Medium, and High findings.
- **Authentication:** A training login should be clearly labelled and isolated per owner; never store raw passwords or imply volatile in-memory accounts are production auth.
